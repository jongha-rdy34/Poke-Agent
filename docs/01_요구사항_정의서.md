# 요구사항 정의서 — Poke-Agent (포켓몬 대전 선출·기술 플래너)

> AI 코어 프로젝트 3회차 · Agent 기반 도메인 플래너 서비스
> 작성: 1일차 (기획 2.1 ~ 2.6)

---

## 1. 도메인 확정 (2.1)

### 1.1 서비스 한 줄 소개
**"내 포켓몬 6마리와 상대 포켓몬 6마리를 보고, 어떤 3마리를 선출하고 각 대면에서 어떤 기술을 쓸지"** 를
실제 메타 통계·종족값·타입 상성으로 **확인한 값만으로** 계산해 제안하는 Agent.

### 1.2 배경
- 포켓몬 팬게임이 늘면서 상대 AI(트레이너 AI)의 수준이 점점 높아지고 있고, 공식 대전(배틀 스타디움 싱글)도
  "6마리를 보여주고 3마리를 선출"하는 구조라 **선출 단계의 판단**이 승패를 크게 좌우한다.
- LLM 혼자 답하면 ① 최신 메타(어떤 기술·도구를 들고 나오는지)를 모르고 ② 종족값·상성을 그럴듯하게 지어낸다.
  → Tool로 확인한 값만 쓰는 Agent가 필요한 주제.

### 1.3 도메인 선택 조건 충족 근거

| 조건 | 충족 근거 |
|---|---|
| **Tool로 래핑할 외부 API 3종 이상** (서로 다른 정보) | ① **Smogon 사용률 통계** — 상대가 실전에서 쓰는 기술·도구·특성·능력치 배분 확률 ② **PokeAPI** — 타입·종족값·특성, 한국어 이름 ③ **Pokémon Showdown 공개 데이터** — 기술 위력·분류·우선도, 타입 상성표. 세 곳 모두 1일차에 코드로 호출 확인 완료 (`docs/04_기획_검증.md`) |
| **판단이 필요한 요청** | "상대 메가한카보다 먼저 때릴 수 있어?" → 스피드 실수치 범위 비교, "누구를 뽑아야 상대 6마리를 다 받아낼 수 있어?" → 상성 배율 × 상대 주력기 비율 조합. 조건을 만족하는 3마리 조합이 없으면 **기준을 바꿔 재계획**할 의미가 있음 (설계 시험에서 실제 발생) |
| **저장·관리할 결과물** | **선출 계획**: 대전 일정(날짜·시작/종료 시각), 포맷, 내 팀/상대 팀, 선출 3마리, 선봉, 대면별 추천 기술과 근거 → 저장·조회·수정·삭제 |
| 판단이 위험한 도메인인지 | 아님 (게임 전략). 건강·금융 면책 문구 불필요. 단, **"통계 기반 추정이며 상대의 실제 세트는 다를 수 있음"** 을 응답에 항상 표시 |

### 1.4 외부 API 출처와 이용 조건 (NF3007)

| API | 용도 | 키 | 호출 한도 / 이용 조건 | 우리 쪽 준수 방법 |
|---|---|---|---|---|
| **Smogon Usage Stats** `https://www.smogon.com/stats/` | 메타 사용률, 예상 세트 (F3002) | 불필요 | 별도 약관·한도 명시 없음. 월 1회 공개되는 정적 파일 (포맷당 3~12MB) | 출처 표기, 월별 파일 디스크 캐시(30일), 같은 파일 재다운로드 금지 |
| **PokeAPI** `https://pokeapi.co/api/v2/` | 타입·종족값·특성·한국어 이름 (F3003) | 불필요 | 공정 이용 정책: 무료, **"요청한 리소스는 로컬에 캐시할 것"**, 남용 시 IP 차단 | 응답 7일 캐시, 한국어 이름은 1회 수집 후 로컬 파일로 재사용 |
| **Pokémon Showdown data** `https://play.pokemonshowdown.com/data/` | 기술 정보, 타입 상성표 (F3004) | 불필요 | 별도 한도 명시 없음. 소스 저장소는 MIT 라이선스 | 파일 단위 24시간 캐시, 출처 표기 |
| (2일차) **SSAFY GMS** | LLM 호출 | `GMS_API_KEY` | 과정 제공 키 | `.env`로만 관리 |

> 포켓몬 이름·데이터의 권리는 Nintendo / Creatures / GAME FREAK에 있으며, 본 프로젝트는 비상업 교육용이다.
> 세 API 모두 키가 없어 "키 발급"은 해당 없음 → 대신 **연결 불가/서버 오류** 상황을 실패 케이스로 검증했다.

## 2. 서비스 시나리오 (2.2)

### 2.1 요청에서 뽑는 조건

| 구분 | 항목 | 예시 | 비어 있을 때 |
|---|---|---|---|
| 기준 조건 | 포맷(규칙), 선출 수 | 싱글 6→3 (`gen9championsbssregmc`), 더블 6→4 | 기본 포맷(싱글 6→3) 사용 + 응답에 밝힘 |
| 기준 조건 | 메타 기준 시점 | "이번 시즌", "2026-10" | 가장 최근 집계월 + 밝힘 |
| 기준 조건 | 내 팀 6마리, 상대 팀 6마리 | 한국어/영문 이름 | **필수 — 없으면 Tool 호출 전에 되묻는다** |
| 선호 조건 | 선호/주력 포켓몬, 플레이 스타일 | "보만다는 꼭 넣고 싶어", "대면 위주" | 없음으로 둠 |
| 제약 조건 | 반드시 잡아야 할 상대 | "메가한카는 꼭 잡아야 해" | 상대 6마리 전체를 대상으로 |
| 제약 조건 | 선공 조건 | "선공 잡고 싶어" | 판단만 하고 강제하지 않음 |
| 제약 조건 | 내 포켓몬의 실제 기술 | "마스카나: 트릭플라워/기습/…" | 메타 통계의 상위 기술로 **가정**하고 가정임을 밝힘 |
| 제약 조건 | 대전 일정 | "토요일 3시 대회 2라운드" | 계획 저장 시에만 필요 — 저장할 때 되묻는다 |

### 2.2 대표 요청과 Tool 호출 순서

| # | 대표 요청 | 의도 | Tool 호출 순서 |
|---|---|---|---|
| R1 | "내 팀 하마돈/마스카나/고릴타/대쓰여너/보만다/루카리오, 상대 팀 누리레느/한카리아스/두랄루돈(진화)/타부자고/따라큐/아머까오. 3마리 뭐 뽑아?" | 선출 계획 수립 | resolve_names → get_meta_usage(상대 6) → get_pokemon_detail(12) → get_move_info(상대 주력기) → get_type_matchup(방어 측별 1회) → **판단** → 응답 |
| R2 | "상대 메가한카 Z보다 내 마스카나가 먼저 때려?" | 대면 판단 | resolve_names → get_pokemon_detail(2) → get_meta_usage(상대: 스카프 비율·배분) → **스피드 범위 계산** → 응답 |
| R3 | "따라큐 상대로 루카리오는 무슨 기술 써?" | 기술 선택 | get_meta_usage(내 루카리오 기술 후보·상대 따라큐 세트) → get_move_info → get_type_matchup(+특성) → 응답 |
| R4 | "한카리아스 종족값 알려줘" | 사실 조회 | get_pokemon_detail → 응답 |
| R5 | "아까 계획 토요일 15:00~15:30 대회 일정으로 저장해" | 계획 확정 | (Tool 없음 — 서버 저장 로직이 직접 처리) |
| R6 | "안녕", "이거 어떻게 써?" | 기타 대화 | Tool 없음 |

### 2.3 재계획이 일어나는 요청 / 되묻는 요청
- **재계획(R1)**: 상대 6마리를 모두 "잡는" 3마리 조합이 없을 때. 설계 시험에서 실제로
  자속 기술 기준으로는 상대 *한카리아스·아머까오* 를 잡는 조합이 없었다 → 기준을 넓혀 재계획 (§ Agent 설계 참조).
- **되묻기**: ① 팀 정보가 6마리 미만/없음 ("상대 팀만 줄게, 뭐 뽑아?") ② 이름이 여러 대상에 걸림(AMBIGUOUS)
  ③ 재계획 3회 후에도 조건 미충족 → "꼭 잡아야 할 상대를 줄이거나 선호 포켓몬 조건을 풀어도 될까요?"

### 2.4 저장할 결과물 — 선출 계획
- 핵심 값: `title`, `battle_date`, `start_time`, `end_time`, `format`, `my_team[6]`, `opponent_team[6]`,
  `selected[3]`, `lead`, `move_plan[{opponent, my_pokemon, move, reason}]`, `basis(통계 월·레이팅)`, `created_at`
- **같은 날짜에 시간이 겹치는 계획**(예: 같은 대회 같은 라운드에 계획 2개)이 있으면 저장은 하되
  겹치는 계획 목록을 저장 결과와 함께 알린다.
